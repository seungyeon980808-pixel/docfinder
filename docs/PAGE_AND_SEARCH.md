# 복수 키워드의 같은 쪽 검색과 방향키 이동

## 계획과 구현

1. 쉼표로 AND 검색어를 나눈다. 공백은 구절의 일부로 유지하며 중복 검색어는 하나로 계산한다.
2. 복수 키워드 본문 검색에는 `같은 쪽에 모두 포함` 옵션을 기본으로 켠다. 모든 검색어가 같은 원문 쪽에 있는 문서만 남긴다. 끄면 기존 문서 전체 AND 검색을 사용한다.
3. 조건에 맞는 쪽만 발췌·쪽 수·위치 수·오른쪽 원문·쪽 목록·미니맵에 반영한다. 원본 쪽 번호와 전체 쪽 수는 유지한다.
4. 왼쪽 문서 선택과 오른쪽 검색 위치 이동을 방향키로 구분한다. 선택 표시와 작업 영역 표시를 유지한다.
5. 로컬 worker, 개인 문서함, 게시 스냅샷, 서버 문서함, 로그인 없는 공유 링크에 동일한 검색 조건을 전달한다. 요청 세대와 검색 조건을 확인해 늦은 응답을 버린다.
6. 다운로드·편집은 전체 원본을 유지한다. 미리보기의 쪽 숨김은 원본 bytes나 편집기를 변경하지 않는다. 자동 버전 교체 중에는 마지막 검색 증거와 읽기 위치를 새 색인이 준비될 때까지 유지한다.

## 사용 방법

- `학생 자치, 회장`: `학생 자치`는 한 구절, `회장`은 두 번째 검색어다.
- 같은 쪽 옵션은 본문에 검색어가 둘 이상일 때만 표시한다. 단일 검색어나 파일 이름 검색은 기존 동작을 유지한다.
- 파일을 클릭하거나 Tab으로 결과 버튼에 초점을 둔 뒤 ↑↓: 다른 문서 선택, →: 원문으로 이동.
- 원문에서 ↑↓: 현재 문서의 이전/다음 검색 위치, ←: 선택한 문서로 복귀. 모바일에서는 원문을 닫거나 다시 연다.
- 검색어별 `이동 대상`은 이동할 키워드만 바꾼다. 같은 쪽 AND 조건은 유지한다. 처음과 마지막 위치에서는 문서를 넘어가지 않는다.
- 검색 입력·IME 조합·편집기의 방향키는 가로채지 않는다. 검색 위치가 없으면 일반 원문 스크롤을 유지한다.
- 쪽 번호 없는 레거시 전체 본문 추출은 같은 쪽 AND 증거로 사용하지 않는다. 문서 전체 검색 또는 단일 검색어로 찾을 수 있다.

## API 호환성

`GET .../search?q=alpha%2Cbeta&mode=content&matchScope=page`

`page`는 같은 쪽 AND, `document`는 문서 전체 AND다. 기존 호출에서 매개변수를 생략하면 `document`를 유지한다. UI는 본문 검색에 `page`를 기본으로 전달한다. 그 외 값은 400으로 거부한다. 로그인·초대·공유 링크 범위·만료·해제 검사는 기존과 같다.

## 배포

코드와 로컬 검수만 수행했다. 운영 서버에 반영하지 않았으며 별도 배포 지시를 기다린다. DB migration, OAuth 권한, Drive 공유 설정, 요금제 변경은 필요하지 않다. 검수 결과는 `evidence/page-and-2026-10-11/RESULT.md`에 기록한다.
