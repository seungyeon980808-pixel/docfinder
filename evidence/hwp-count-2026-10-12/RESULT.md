# 한글 문서 일치 수 수정 검수

## 원인과 수정

한글 문서의 문단 텍스트만 추출하던 색인이 도식의 텍스트 상자를 누락했다. 원문 강조는 페이지 레이아웃의 텍스트를 사용하여 검색 목록과 수가 달랐다.

색인과 원문 강조가 같은 페이지 텍스트와 연결 규칙을 사용하도록 통일했다. 한글 색인 버전은 3이며, 배포 후 기존 HWP/HWPX를 백그라운드에서 다시 색인한다. 기존 쪽은 새 결과를 게시할 때까지 유지한다. 원본 파일과 접근 권한은 바꾸지 않는다. 재색인 버전이 문서함 및 공유 링크의 캐시 리비전에 반영된다.

## 로컬 검수

- 문제 문서의 같은 쪽 AND 검색: 수정 전 색인 103개 / 원문 105개. 수정 후 모두 105개, 9쪽.
- 누락이 발생한 2쪽: 수정 전 색인 5개 / 원문 7개. 수정 후 모두 7개.
- 전체 쪽별 수가 일치함: `actual-counts.json` (개인 문서 내용은 포함하지 않음).
- 자동 테스트 206/206 통과. 구버전 재색인, 실행 중 작업 보호, 반복 예약 방지, 기존 쪽 보존, 원본 유지, 소유자 및 공유 캐시 무효화 검증 포함.
- Chromium 데스크톱, WebKit 데스크톱/모바일 회귀 검수 통과: `browser-qa.json`.
- 원본 DPR, 입력·선택·스크롤·IME, 늦은 응답 보호, 다운로드, HWP 편집·확대·사본 저장·실행 취소·다시 실행 유지 확인.
- native Safari에서 로컬 문서함과 한글 원문이 열리는 것을 확인했으나, 이후 UI 검수 도구가 응답 시간 초과하여 검색 수 확인은 완료하지 못함.
